# Roadmap

Features planned next, in the order they will be built. Each note says what it is and where it starts in the code, so work can pick up without rediscovering the design.

## 1. Deploy a saved version, and see drift

- Deploy a numbered version instead of the draft: `POST .../deployments` takes `{"version": n}` and copies `versions/{n}.json` instead of `draft.json`. The Deploy panel lets you pick it.
- Show and create versions in the app (the API already has them: `POST/GET .../versions`).
- Compare the diagram with what is deployed: a plan with no changes means no drift. Run a `terraform plan -refresh-only` phase in the engine (`services/engine/runner`) and show what changed outside Rivo.

## 2. Lambda logs and test invocations

- In the inspector of a deployed Lambda, show its recent CloudWatch logs and invoke it with a test event, like the console.
- A Lambda in the API assumes the connection's role (as `verify-connection` does) and calls `logs:FilterLogEvents` and `lambda:Invoke` on the function named in the project's endpoints, never on a name the request sends. Add its role to the trusted roles in `infra/api/engine.tf` and to the template in `models/connection`.

## 3. Upload a static site build

- Let a bucket served by CloudFront take a `.zip` of a site build, as a Lambda takes one, instead of the placeholder page.
- Reuse the package upload (`services/package`). `tfgen` writes one `aws_s3_object` per file, with its content type, or the runner syncs the files after the apply.

## 4. A DynamoDB explorer

- Browse, filter, add and edit items of a deployed table from its inspector, including queries on its indexes.
- Same pattern as item 2: a Lambda that assumes the role and only touches tables in the project's endpoints. Page results and cap their size.

## 5. Cost estimate before approving

- Show what the plan will cost per month next to its summary.
- Price each resource type in `plan.json` from the AWS Price List API, with usage assumptions the person can change (requests, storage). Mark it as an estimate.

## 6. API authentication and custom domains

- JWT authorization on HTTP APIs with a Cognito user pool, generated by `tfgen` (today `authorizationType` is only a warning).
- Custom domains for API Gateway and CloudFront, with ACM certificates and Route 53 records.

## 7. Secrets

- Secret environment variables stored in Secrets Manager, never in the diagram. The function gets the secret's ARN and permission to read it, and the value is set outside Terraform's state.

## 8. Python dependencies

- Install `requirements.txt` for functions written in the editor, in a separate build task with no AWS permissions, and hand the resulting `.zip` to the engine like an uploaded package. Never install packages inside the engine: package installs run code.

## 9. SQS and SNS

- Generate queues and topics: Lambda → SQS (send), SQS → Lambda (event source mapping), SNS → Lambda and SNS → SQS subscriptions. Update `connections.ts`, `readiness.ts` and the schemas with `tfgen` (see "The generator and the canvas share keys" in `CLAUDE.md`).

## Later

- Project-level access, so a workspace can limit who sees each project.
- A platform administration screen for accounts.
- VPCs with their subnets.
- Push the diagram and Terraform to a GitHub repository through a GitHub App.
